# DeployReady

DeployReady is an offline deployment inspection workbench for beginners building Vite/React projects.

It scans project configuration without running the target project, exports a versioned JSON report, and provides a React dashboard for exploring evidence, coverage, and before/after changes.

> DeployReady reports configuration signals. Passing its checks is not proof that a project will deploy successfully or behave correctly at runtime.

## What it checks

The initial Vite/React profile evaluates:

1. Missing or empty `package.json` build script.
2. Missing, conflicting, or mismatched package-manager lockfiles.
3. Missing, invalid, or incompatible Node version declarations.
4. Literal `import.meta.env.VITE_*` names missing from an environment template.
5. Literal HTTP/HTTPS URLs pointing at localhost or loopback addresses in application source.
6. Git-tracked non-template `.env` files.

Every check reports one of:

- `passed` — the evaluated rule found no finding.
- `finding` — the evaluated rule found one or more actionable findings.
- `not_checked` — the rule could not safely evaluate all required input.
- `not_applicable` — the rule has no relevant input for this project.

Skipped checks are never treated as passed, and a skipped current check cannot make an older finding appear resolved in comparison.

## Requirements

- Node.js `22.19.0` or a compatible Node 22 runtime.
- npm.
- Git for the tracked-environment-file check.

The scanner does not need network access after dependencies are installed.

## Install and verify

```bash
npm ci
npm run typecheck
npm test
npm run build
```

## Run the CLI

The local CLI accepts a project path and never executes that project’s scripts.

```bash
# Human-readable terminal output
npm run deployready -- scan /path/to/vite-project

# Export a validated JSON report
npm run deployready -- scan /path/to/vite-project \
  --format json \
  --output deployready-report.json \
  --fail-on warning

# Validate a report before importing it elsewhere
npm run deployready -- validate-report deployready-report.json

# Compare two reports from the same project
npm run deployready -- compare before.json after.json
```

Useful options:

- `--fail-on error|warning|info|none` — CI threshold; defaults to `error`.
- `--strict-coverage` — return the partial-coverage exit code when any required check is skipped.
- `--max-file-bytes`, `--max-files`, `--max-total-bytes` — bounded scan limits.
- `--format pretty|json` and `--output <path>` — terminal or machine-readable output.

Exit codes:

| Code | Meaning |
| ---: | --- |
| 0 | Completed without a finding at the configured threshold |
| 1 | A finding met the configured threshold |
| 2 | Invalid input, malformed report, unsupported report, or incompatible reports |
| 3 | Fatal scanner or command failure |
| 4 | Partial coverage with `--strict-coverage` |

## Run the dashboard

```bash
npm run dev
```

Open the local Vite URL shown in the terminal. The dashboard starts with a clearly labelled synthetic sample report. Use **Import JSON report** to load a report generated by the CLI.

The dashboard validates reports locally before rendering them. It has no authentication, database, repository connection, runtime AI, or server-side scanner.

### Review and remediation workflow

- Expand a finding and choose **Include in fix prompt**, or use **Create fix prompt** beside it.
- Review the deterministic, editable Markdown preview. **Copy prompt** uses the Clipboard API when available and a selectable fallback otherwise; **Download Markdown** saves the same current preview text.
- Use **Import Lighthouse JSON** for a local Lighthouse export. The browser adapter preserves category scores, audit states, evidence bounds, warnings, and limitations without launching Chrome or contacting the URL.
- Lighthouse audits stay separate from the DeployReady scan until you explicitly confirm that the export belongs to the current project. Only selected failed, actionable audits can then enter the prompt; no combined readiness score is calculated.
- Coverage distinguishes files skipped by bounds or safety limits, deliberate environment-file content exclusion, and checks that were unavailable. None of those states is treated as a pass.

For a production bundle:

```bash
npm run build:dashboard
```

The static bundle is written to `apps/dashboard/dist/`.

### Local browser verification

The production bundle was also audited locally in Chrome DevTools using Lighthouse `13.5.0` with mobile emulation against `http://127.0.0.1:4173/` on `2026-10-19T18:35:41.744Z` (the report's UTC `fetchTime`). The initial recorded category scores were Performance `89`, Accessibility `97`, Best Practices `100`, and SEO `100`. After the contrast fix, a second real mobile audit recorded Performance `88`, Accessibility `100`, Best Practices `100`, and SEO `100`. These were real audits of the local production bundle, separate from the clearly labelled synthetic Lighthouse fixture and not hosted deployment results.

Both audits warned that installed Chrome extensions affected load performance. DeployReady therefore does not treat the contaminated JavaScript-size or performance observations as optimization evidence or claim a clean benchmark. The actionable accessibility finding was insufficient contrast on secondary metadata and table/footer text; the affected neutral text token was darkened while preserving the cream/navy/teal visual system. The real Lighthouse export was imported and rendered in the dashboard; its Lighthouse evidence remained excluded from remediation until the explicit same-project association gate was confirmed. The large raw JSON export remains outside this repository.

## Scan-to-compare demo

The repository includes small synthetic projects for the demo and test suite:

- `fixtures/projects/clean-vite-react`
- `fixtures/projects/broken-vite-react`
- `fixtures/projects/corrected-vite-react`

Generate reports and compare the broken and corrected versions:

```bash
mkdir -p reports
npm run deployready -- scan fixtures/projects/broken-vite-react \
  --format json --output reports/broken.json --fail-on none
npm run deployready -- scan fixtures/projects/corrected-vite-react \
  --format json --output reports/corrected.json --fail-on none
npm run deployready -- compare reports/broken.json reports/corrected.json
```

The fixture directories are intentionally not full applications with installed dependencies. They provide deterministic configuration and source inputs for inspection. DeployReady does not run their package scripts.

## Safety and privacy

- The scanner is read-only with respect to the target project.
- Target `npm`, `pnpm`, `yarn`, `bun`, and Vite scripts are never executed.
- Git inspection asks only for tracked filenames and never reads tracked `.env` contents.
- Environment-template checks compare variable names, not values.
- Source evidence is bounded and loopback URLs are represented as host/protocol metadata rather than full source lines.
- Symlinks, binary files, generated directories, oversized files, and project-wide limits are handled as explicit coverage decisions.
- Reports contain relative paths and are rejected by the CLI if they contain absolute local paths.
- The browser validates imported JSON against the report contract and renders values as escaped text.

The Dockerfile uses Node `22.19.0`, installs from the lockfile, builds the dashboard, and defaults to the test command.

```bash
docker build -t deployready .
docker run --rm --network none deployready npm test
```

The second command is deliberately network-disabled. GitHub Actions run `39304457396` (commit `816e37c`) completed clean `npm ci`, all 42 tests, typecheck, production build, Docker image build, and Docker tests with `--network none`. Docker is therefore verified in CI; local Docker availability is not required to use the scanner or dashboard.

## Release verification and demo path

The reproducible release path is:

1. Run `npm ci` on Node `22.19.0` (the pinned `.nvmrc` runtime).
2. Run `npm test -- --run`, `npm run typecheck`, and `npm run build`.
3. Run `npm run dev`, open the local Vite URL, and review the labelled synthetic report.
4. Use **Import JSON report** with a CLI report, then expand a finding and select **Include in fix prompt** or **Create fix prompt**.
5. Edit the deterministic Markdown preview, then use **Copy prompt** or **Download Markdown**.
6. Use **Import Lighthouse JSON** with a local export. Confirm the explicit same-project association only when appropriate; select failed actionable audits only after association.

These checks demonstrate reproducible local tooling and report-review behavior. They do not certify a deployment, prove runtime correctness, or imply a hosted Lighthouse score. The dashboard never applies fixes, launches Chrome, fetches arbitrary URLs, or creates a combined readiness score.

## Architecture

- `packages/report-contract` — versioned report types, schema, and validation.
- `packages/scanner-core` — Node-only bounded filesystem/Git inspection and six rules.
- `packages/comparison` — pure, coverage-aware report comparison.
- `packages/cli` — local scan, validation, and comparison commands.
- `packages/lighthouse-adapter` — bounded, browser-safe parsing of local Lighthouse JSON exports.
- `packages/fix-prompt` — deterministic, redacted remediation prompt generation.
- `apps/dashboard` — static React/Vite report viewer.

The hosted dashboard is a report viewer. Local inspection stays local so a project does not need to upload source code or credentials.

## Limitations

DeployReady initially supports root-level Vite/React projects and direct static source patterns. It does not:

- Execute a project build.
- Contact a deployment provider.
- Validate provider-specific settings or platform-injected variables.
- Resolve dynamic environment access or dynamically assembled URLs completely.
- Apply automatic source fixes.
- Inspect a full monorepo dependency graph.
- Launch Chrome or run a Lighthouse audit; Lighthouse JSON is imported as local evidence only, and no real Lighthouse audit is bundled with this repository.
- Run Docker locally when Docker or Podman is unavailable; the CI Docker verification above remains the authoritative container check for this repository.
- The targeted Vitest `5.0.5` upgrade addresses the previously reported development-tool advisories. Current `npm audit` and `npm audit --omit=dev` both report zero vulnerabilities. Reassess future toolchain advisories when dependencies change.

Use the report as a preflight aid, then run the real project build and the deployment platform’s own validation.
